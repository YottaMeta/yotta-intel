# 元情常见问题

## 速查索引

- **提取**：为什么没提出 IOC · 哈希为什么漏了 · 域名为什么误报
- **格式**：defang 没还原 · CSV/JSON 怎么选 · STIX 怎么用
- **报错**：文件读不了 · 退出码是什么意思
- **安装**：装到哪个目录 · 和元钥/元察怎么分工

---

## 1. 为什么文本里有地址却一个 IOC 都没提取？

先确认文本是普通报告、钓鱼邮件还是日志：纯文本用 `extract --path`，管道内容用 `extract --stdin`。若原文被 `[.]`、`hxxp` 等去活性写法包裹，`extract` 会先做 refang 预处理，理论上也能命中；仍为空时可先用 `refang` 看还原结果，再检查 IOC 是否属于被类型过滤或 `--min-count` 过滤的范围。

## 2. 提取结果把 `README.md`、`test.py` 当域名了？

不会。引擎对常见的文件名后缀（`.md`、`.py`、`.sh` 等）做了过滤，也要求域名至少两级且 TLD 在白名单内；单标签、纯数字 TLD 都会被拒绝。

## 3. 为什么某些 32/40 位十六进制没有被当哈希？

哈希必须满足长度且不能被识别为 UUID 等其它格式；若十六进制串嵌在普通句子或代码里，可能被当作普通 token 跳过。要确认某段是否真的是哈希，可以把它单独放一行或用 `verify` 类工具复核；本引擎只提取明确形态。

## 4. defang 文本没有被还原？

先确认写法是否属于支持的形态：`[.]`、`(.)`、`[dot]`、`hxxp`、`[@]`、`[:]`、`[/]` 等均支持；大小写不敏感。若用了自定义分隔符（如 ` DOT `、URL 编码），引擎不会猜测，需先还原成标准形态。

## 5. CSV、JSON、STIX 怎么选？

给表格/平台导入用 CSV；给程序或自动化下游用 JSON（结构完整、含来源与行号）；要生成 STIX 2.1 Bundle 供 SIEM 或情报平台导入用 `--format stix`。

## 6. STIX 输出和 JSON 里的 IOC 数量为什么可能不同？

JSON/CSV 会保留去重后的七类 IOC；STIX-lite 也按同源生成 indicator，字段以规范文档为准。若你在 STIX 里看不到某类型，先检查该类型是否被 `--types` 过滤或引擎判定为无效格式。

## 7. 提示文件不存在/读取失败，退出码是什么？

文件不存在、无输入、未知类型等用法或读取错误统一为退出码 4；`extract` 成功但未发现 IOC 为 0，发现 IOC 为 1。`--stdin` 模式请确保确实有管道输入。

## 8. 可以传目录吗？

`extract` 面向单文件或 stdin；要批量处理目录请由 AI 遍历文件后逐个提取，或在脚本里对每个文件调用一次。`defang/refang` 同样按单文件/流处理。

## 9. 输出里 `count` 和 `first_line` 怎么理解？

`count` 是同一 IOC 在文本中出现的次数；`first_line` 是首次出现的行号；`snippet` 是上下文片段。用 `--min-count 2` 可过滤只出现一次的噪音。

## 10. 我能在邮件/群聊里直接分享原始 IOC 吗？

建议先 defang。原始 URL/邮箱/域名可能被平台自动转成可点击链接，误触或触发沙箱外联；`defang` 会保留可读性并去掉活性。

## 11. 安装不上/智能体没识别怎么办？

用 `npx -y @yottameta/yotta-intel --agent <名称>` 装到已知智能体，或 `--dir <技能目录>` 装到自定义路径；未收录智能体不要靠猜目录，直接 `--dir`。若走 npm 镜像遇到传播延迟，临时加 `--registry=https://registry.npmjs.org/`。

## 12. 元情和元钥、元察怎么分工？

元情只做威胁情报文本里的 IOC 提取/归一/格式转换；元钥负责源码/配置里的密钥泄露扫描；元察负责安全日志检测。输入是报告/邮件/日志文本时优先元情，输入是代码/配置仓库时用元钥。
